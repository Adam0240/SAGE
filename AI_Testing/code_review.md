### R1 — Credential-shaped value in the distributed environment template

- **Severity / status:** High; tracked exposure confirmed, credential validity and privileges unverified.
- **Location:** `.env.example:16`, the `sage-local-scan` comment; `.github/workflows/tests.yml:50`, release file list.
- **Issue:** The template contains a full `sqp_`-prefixed Sonar-token-shaped value. A comment still exposes its contents to repository readers, and the template is included in the release archive. Whether it remains usable cannot be determined from source.
- **Recommendation:** Have the owner revoke/rotate it if it is or was a real credential, remove its value from the template, and inspect previously distributed artifacts/history for exposure. Keep actual scanner credentials in the established secret configuration. Do not validate it by making an unsolicited service request.
- **Benefit:** Removes accidental credential distribution and closes access if the value is active.
- **Regression risk:** Low for removing the comment; rotation can disrupt any scanner still using the old credential, so update that configuration together.
- **Status:** Fixed, removed the secret key from the .envexample file.

### R2 — Print permission survives account deletion, deactivation, or role revocation

- **Severity / status:** High; confirmed authorization design defect.
- **Location:** `services/session_service.py:26`, `SessionState.can_start_print`; `main.py:335`, `_open_gcode_app`; `services/octoprint_print_service.py:34` and `:69`, `start` / `_checked`.
- **Issue:** Both print authorization checks invoke a callback that reads the immutable role snapshot taken at login. Neither checks that the account still exists, is active, or still has `steam_specialist` permission in PostgreSQL. A specialist deleted by another admin can continue printing until logout. Account mutations correctly reload locked actors, but the print path does not share that protection.
- **Recommendation:** Revalidate the authenticated account asynchronously at the print authorization boundary, fail closed on missing/revoked/unavailable authorization, and invalidate the stale session. Preserve the current restriction that Boss Admin and assistants cannot print. Avoid synchronous database reads from `_update_print_button`, which runs frequently on the GUI thread.
- **Benefit:** Makes revocation effective for equipment control without freezing the interface.
- **Regression risk:** Medium: valid staff printing will depend on successful revalidation. Test deletion/demotion/deactivation after login and during preflight, unavailable database, and logout during the check; assert zero POSTs in denied cases.
- **Status:** Fixed (November 24, 2026). Print submission now revalidates the account's existence, active state, and `steam_specialist` role in a fresh database session on a background thread after printer preflight. Revoked permission rejects the print and returns the matching launcher session to Student Mode. Database errors/timeouts fail closed without submitting or retrying a print. Logout, replacement login (including the same account), navigation, and shutdown invalidate pending authorization; late results cannot submit or log out a replacement session. The GUI's routine print-button updates remain database-free, and abandoned checks are limited to one worker per print service. Validation: **446 unit/UI tests and 187 subtests passed**; changed production files passed Ruff (`E4,E7,E9,F,I`), and `git diff --check` passed. Regression tests cover fresh deleted/inactive/demoted account state, revocation during preflight, unavailable database and recovery, UI responsiveness, logout/relogin, Home cancellation, timeout, late results, worker limits, and launcher invalidation. All database checks were mocked and HTTP requests used loopback stand-ins; no production database or equipment was contacted. This is fresh authorization at submission, not an atomic transaction spanning PostgreSQL and OctoPrint: revocation after the final database read cannot retract an already submitted command.

### R3 — AI guardrails do not protect the spoken equipment answer

- **Severity / status:** High; confirmed with an injected model response.
- **Location:** `services/ai_assistant_service.py:11`, `SETTING_PATTERN`; `:50`, `respond`, especially `:137`; `services/home_voice_controller.py:494`, `on_voice_ai_response`.
- **Issue:** The numerical filter recognizes only a small set of units and checks a set of values, not their meaning. `999 C`, spelled-out settings, unitless values, and invented nonnumeric procedures can pass. Even a documented value can be attached to a different setting. The displayed answer appends the original reference, but `spoken_text=answer` omits that reference and its mandatory cautions. An offline fixture containing “Staff supervision is required” and “Stop the printer and ask staff” accepted a generated answer with an undocumented temperature and cover-removal instruction; the extracted settings set was empty, and speech contained only the generated text.
- **Recommendation:** Use the existing documentation-based response for spoken equipment procedures unless the wording can be reliably validated. Preserve required cautions in every delivered channel. Treat the regex as a limited additional check, not proof of grounding; simply adding more units cannot validate arbitrary procedures. Add mocked omissions, changed setting associations, unsupported units, and invented action cases.
- **Benefit:** Prevents the voice path from presenting unverified procedures as source-backed instructions.
- **Regression risk:** Medium: spoken replies become longer or less conversational. Preserve clarification, unavailable-document, and offline fallback behavior. This finding demonstrates acceptance of a bad response, not its frequency with the deployed model.
- **Status:** Fixed (November 24, 2026). Spoken equipment answers now use the existing documentation response, preserving the retrieved instructions, ancestor cautions, staff-supervision requirements, and partial-read notices on both successful generation and rejected numerical settings. Empty answers and model failures retain the documentation fallback. Displayed summaries are labeled AI-generated with an instruction to verify against the original reference, which remains visible; the numerical regex is explicitly only an additional check, not validation of arbitrary procedures. Regression tests cover omitted cautions, unsupported units, spelled-out and unitless settings, invented actions, valid numbers associated with the wrong setting, recognized unsupported settings, empty responses, and the actual home-controller handoff to speech. Validation: **456 unit/UI tests and 187 subtests passed**; the changed production service passed Ruff (`E4,E7,E9,F,I`). Tests used mocked AI and speech; no live equipment or production database was contacted. Spoken replies can be longer. Generated screen summaries remain unverified, and safety context omitted by retrieval remains the separate R4 finding.

Have the room's documentation owner approve the associations; do not invent equipment guidance.
- **Benefit:** Makes both deterministic fallback and generated answers retain the tutorial's intended restrictions.

The former standalone “Material and Equipment Safety” content is now at the start of the laser document; procedure headings and their source identities remain intact. Nine real-document regression cases verify the selected topic and cautions in displayed references, spoken answers, and model prompts across deterministic, generated, and offline responses. Validation: **465 unit/UI tests and 187 subtests passed**, including existing negation, ambiguity, and repeated-heading isolation coverage; the changed test file passed Ruff (`E4,E7,E9,F,I`), and scoped `git diff --check` passed. ### R5 — Cancelling home voice leaves printer-status callbacks active

- **Severity / status:** Medium; confirmed offline.
- **Location:** `services/home_voice_controller.py:297`, `check_printer_status`; `:310`, `on_printer_status_completed`; `:590`, `cancel`.
- **Issue:** `cancel()` cancels speech, AI, and project searches, but does not cancel `printer_status_service` or reset `_printer_status_pending`. After navigation or opening login, `_closing` remains false, so the old status result calls `speak_response`. It can also reset the button or start playback during a subsequent recording. The offline probe produced `Status cancel called: False` and `Late status speaks: True`.
- **Recommendation:** Reset pending status and cancel its service on every voice cancellation. Use request identity if overlapping replacements remain possible. Add a held-status test for navigation, login/logout, and a new voice turn.
- **Benefit:** Stops abandoned requests from changing the current voice interaction.
- **Regression risk:** Low: ensure an intentionally requested fresh status still completes and cancellation does not issue equipment commands.
- **Status:** Fixed (November 24, 2026). Every home-voice cancellation clears the pending-status gate before cancelling `PrinterStatusService`, which already discards abandoned printer/job replies by identity. Held-reply regressions cover both request stages during navigation, login/logout, shutdown, a new recording, and a replacement status request; old replies cannot speak or alter the current button, while fresh status still completes. The full unit/UI run passed **482 tests and 195 subtests**. The changed production files passed Ruff (`E4,E7,E9,F,I`); the preexisting import ordering in the touched home controller was corrected. No live equipment was contacted.

### R6 — The file printed is not tied to the version that was previewed

- **Severity / status:** Medium; confirmed missing check, consequence conditional on remote replacement.
- **Location:** `services/octoprint_file_service.py:119`, `metadata_received`; `sage_apps/gcode_display_print_app.py:417`, `_remote_file_ready`, and `:508`, `start_print`; `services/octoprint_print_service.py:69`, `_checked`.
- **Issue:** Download caching uses remote hash/date/size, but only the path and server source reach the print service. `_file_validated` means a download previously succeeded. If another OctoPrint user replaces that path after preview, the subsequent command prints the replacement, with no changed-file notice. A fresh printer-idle check does not validate file identity.
- **Recommendation:** Retain the selected version metadata and recheck it before print submission; on change, invalidate selection/preview and require review again. State the remaining check-to-use limitation if the server cannot atomically bind selection to a version; do not claim a metadata check alone makes the operation atomic.
- **Benefit:** Detects ordinary remote file replacements and reduces mismatch between preview and submitted job.
- **Regression risk:** Medium: unversioned servers require a defined conservative behavior. Use the loopback server to replace a same-named file between preview and print, preserving existing no-retry and permission tests.
- **Status:** Fixed (November 24, 2026). Preview completion retains the server's hash/date/size metadata. Print submission now re-reads and validates metadata after printer preflight and fresh database authorization, checks that the staff session is still current, and submits only if the version matches. A changed, missing, inaccessible, malformed, timed-out, or unverifiable file rejects submission, clears the displayed preview and its print approval, and requires review again. A nonempty hash or a valid date plus size is required; size alone cannot authorize printing. Navigation cancels metadata checks, and stale callbacks cannot submit. Loopback tests cover same-path/same-size replacement, replacement during authorization, date/size-only servers, re-preview and successful recovery, metadata failures, timeout, cancellation, and logout; existing permission and no-retry regressions pass. The full suite passed **482 tests and 195 subtests**; scoped diff checks and production Ruff checks passed. AI/database checks were mocked and HTTP used loopback stand-ins. This is not an atomic file-version selection: replacement after the final metadata read, or replacement that preserves all reported version fields, remains undetectable. Authorization and metadata checks are also separate; revocation after the database read cannot retract a submitted command.

R5/R6 final follow-up validation: after separating the new-recording and replacement-status cases and tightening cache reuse to validated versions, **91 focused tests and 15 subtests passed** (`test_home_voice.py` and `test_octoprint_files.py`).

### R7 — Cancel/reopen cycles can accumulate live AI requests

- **Severity / status:** Medium; confirmed lifecycle behavior, exhaustion risk conditional on repeated use and slow service.
- **Location:** `services/ai_response_worker.py:84`, `AIResponseLoader.cancel`, especially `:91`; `:94`, `_start_pending`.
- **Issue:** Cancellation sets the event and drops `self.thread` while the synchronous `client.chat` remains in progress. Each reopen/new request can start another daemon and model request. Stale results are safely discarded, but no limit governs the abandoned requests. A timeout per request does not bound the number of concurrent requests.
- **Recommendation:** Bound in-flight work, including abandoned requests, and retain enough lifecycle state to release their resources. Preserve responsive navigation and stale-result suppression; avoid blocking the GUI while waiting. Do not create a general worker framework solely for this fix.
- **Benefit:** Prevents repeated navigation from overloading the local model or growing thread/socket usage.
- **Regression risk:** Medium: `test_home_reopen_submits_without_waiting_and_rejects_stale_answers` deliberately requires a replacement to start immediately. Preserve that for ordinary use while defining and testing a finite cap under repeated cancellation.
- **Status:** Fixed (November 24, 2026). A process-wide two-slot limit now bounds AI response workers across Home and guide instances, including cancelled requests and destroyed widgets. An abandoned worker retains its slot until its `finally` block releases it. The ordinary first replacement can start immediately; at capacity each loader retains only its latest pending question and checks capacity through the existing Qt timer. Cancellation drops pending work, stale-result filtering remains in place, and thread-start failure releases the reserved slot. A held-worker regression destroys one loader, repeatedly cancels/submits through another, verifies that only two workers start, and confirms that only the latest pending question runs after capacity returns. The existing immediate-reopen and teardown regressions pass. Validation: **496 unit/UI tests and 195 subtests passed**; changed production files passed Ruff (`E4,E7,E9,F,I`). No live model/server was contacted. A permanently blocked call still occupies its slot, so at capacity new work waits; the fix bounds concurrency rather than forcibly interrupting Ollama.

### R8 — Native microphone/model stalls have no recovery deadline

- **Severity / status:** Medium; documented code limitation, actual hardware stall not observed.
- **Location:** `services/speech_recognition_service.py:100`, `_record_and_transcribe`, and `:141`, `_capture_audio`; `services/home_voice_controller.py:169`, `toggle_speech`.
- **Issue:** Recording duration checks execute only after blocking reads return; model load/decoding are also cooperative. A stuck native call leaves `_is_recording` true. Navigating away suppresses callbacks but does not make the microphone service reusable, and retries are rejected indefinitely. `services/SPEECH.md` correctly documents this limitation.
- **Recommendation:** Establish bounded handling for the deployment audio stack, preferably using supported stream cancellation/timeouts; use process isolation only if native calls cannot be stopped reliably. At minimum make the recovery requirement explicit and validate failure/restart on the deployment device before enabling public voice use.
- **Benefit:** Avoids a voice feature that remains unusable after a device failure.
- **Regression risk:** Medium to High for lifecycle changes: preserve single ownership of the microphone, model reuse, late-callback suppression, and prompt UI shutdown. Existing cooperative cancellation tests do not establish recovery from a permanently blocked driver.
- **Status:** Implemented for Home (November 24, 2026); deployment-device acceptance remains pending. Home now uses `SupervisedSpeechRecognitionService`, which runs the existing engine in one reusable spawned process and supervises it off the Qt thread. Capture/startup has a 30-second default deadline; model loading/transcription has a 120-second deadline. Cancellation allows one second of cooperative cleanup, then terminates the child, escalating to kill if needed. A new recording cannot start until the old process is confirmed dead; failure to terminate disables further starts until SAGE restarts. Normal requests reuse the process/model, cancelled callbacks remain suppressed, and timeout/unexpected-exit errors permit a manual retry. Navigation cancels active work; shutdown and QObject destruction dispose of the worker without blocking Qt. The application entry point includes Windows `freeze_support()`. Eleven real-subprocess tests use fake engines blocked permanently in capture, model loading, transcription, and segment iteration, checking termination before retry, cancellation, process/model reuse, unexpected exit, and prompt shutdown. Validation: **496 unit/UI tests and 195 subtests passed**; all **11 supervisor tests** passed again after final cleanup/error-reporting refinements, and scoped Ruff/diff checks passed. No microphone, model weights, or live equipment were used. `services/SPEECH.md` documents deadlines, ownership, and required disconnect/reconnect/retry/shutdown acceptance on the deployment device. Direct callers of the original `SpeechRecognitionService` retain its cooperative engine contract; Home uses the supervised wrapper. Process termination cannot by itself prove recovery of every physical driver, so hardware acceptance is not claimed complete.

### R9 — Versioned disk caches grow without eviction and require installation-directory writes

- **Severity / status:** Medium; confirmed design, disk exhaustion/permissions failure conditional on deployment.
- **Location:** `services/octoprint_file_service.py:119`, `metadata_received`; `services/gcode_preview_service.py:32`, `get_preview`; `sage_apps/gcode_display_print_app.py:35`, `THUMB_DIR`.
- **Issue:** Each changed file version creates a new G-code and PNG entry with no total size/count/age limit. The 128 MB limit is per download, not per cache. The default cache lives under the source installation. Rendering can survive an unavailable PNG cache, but remote downloads require a writable directory and fail in a read-only install.
- **Recommendation:** Use an appropriate writable per-user application cache and a modest total budget/expiry policy. Evict only cache-owned, inactive entries; preserve atomic download writes and configuration/version separation.
- **Benefit:** Predictable disk use and successful previews under a standard restricted desktop account.
- **Regression risk:** Medium: eviction must not remove an active download or image source. Test a full/read-only cache and cleanup during selection changes; keep existing cache invalidation cases.
- **Status:** Fixed (November 25, 2026). The viewer defaults to `SAGE` under Qt's per-user cache location, with an absolute home-directory fallback rather than the installation directory. Managed G-code entries have a 512 MiB/128-file budget; PNG entries have a 64 MiB/512-file budget; inactive entries expire after 30 days. Cleanup removes oldest-accessed owned entries and runs during cache use/release. Entry leases protect downloads, selected files, and rendering sources; reference counts coordinate threads and `QLockFile` prevents eviction of entries locked by another process. Cleanup skips symlinks, unrelated/legacy files, and temporary files. Selected-file leases release on cancellation, selection change, errors, and QObject destruction. Download writes remain atomic, and PNG writes now use `QSaveFile`; cancelled PNG saves explicitly close their temporary handles. Unavailable PNG storage still permits rendering; unavailable download storage reports a cache error without validating the file. Regression coverage includes byte/count/age eviction, recent-access ordering without changing version mtime, active and nested leases, external locks, symlink/path containment, permission failures, cleanup during rendering and selection changes, destruction, failed saves, and existing configuration/version invalidation. Validation: **511 unit/UI tests and 195 subtests passed**; the focused run passed **57 tests and 24 subtests**; scoped Ruff (`E4,E7,E9,F,I`) and diff checks passed. Tests used temporary directories and loopback HTTP, with no live equipment or production database. Budgets are best effort: active entries, failed deletions, and temporary writes can exceed them until cleanup is possible. Legacy/unrelated files are intentionally outside the managed budget. The policy is documented in `README.md`.

### R10 — Unsupported coordinate modes produce a plausible but incorrect preview

- **Severity / status:** Medium; confirmed with a temporary file.
- **Location:** `services/gcode_parser.py:14`, `read_gcode_coordinates`; `services/gcode_preview_service.py:32`, `get_preview`.
- **Issue:** The parser ignores modal commands such as `G91` and applies all X/Y values as absolute positions. `G90; G1 X10 Y10; G91; G1 X5 Y0; G1 X5 Y0` (one command per line) yielded `(10,10), (5,0), (5,0)` rather than relative moves to `(15,10), (20,10)`. Similar limitations exist for resets/units and unsupported movement; the preview is not a full toolpath validator.
- **Recommendation:** Detect unsupported coordinate modes and give an explicit unavailable/limited-preview result instead of silently presenting the geometry as accurate. Full G-code interpretation is unnecessary for this review's scope. Keep the existing supported straight-line behavior and clarify the preview limitation at the point of use.
- **Benefit:** Avoids misleading users reviewing a selected file.
- **Regression risk:** Low to Medium: some previously displayed files will be rejected. Add relative/reset-mode fixtures and retain existing syntax/omitted-axis tests. This does not claim that SAGE modifies the downloaded G-code sent to the printer.
- **Status:** Fixed (November 25, 2026). The parser explicitly rejects unsupported G commands, relative/inch modes, axis resets, arcs, numbered lines, and multiple G commands per line instead of returning partial geometry. Absolute millimetre G0/G1 moves, G4 dwell, and extruder-only G92 remain supported. The viewer shows an explicit unsupported-preview message and a permanent approximate-XY/slicer-review notice. A cache-format key change prevents reuse of earlier misleading PNGs. Validation: **47 parser/service/viewer tests and 33 subtests passed**, followed by the new UI regression confirming an unsupported mode clears a prior valid image (**1 passed**). No G-code is rewritten and no printer was contacted.

**R10 regression correction (November 25, 2026):** The initial filter was too restrictive: all eight locally cached user files contained ordinary `G28` startup homing and were rejected. Startup homing is now allowed before XY movement. Homed XY axes remain unknown until the first absolute XY move explicitly supplies them, so the preview does not invent a home coordinate or draw the homing path. Homing after XY movement, relative/inch modes, coordinate resets, and other unsupported movements remain rejected. Error messages now identify the rejected command or condition. The preview cache key was advanced. Validation: **51 parser/service/viewer tests and 37 subtests passed**; scoped Ruff/diff checks passed. Read-only verification of the eight cached user files rendered **seven successfully** into a temporary image cache; **one exceeded the existing 500,000-coordinate limit**, which is separate from the homing regression and unchanged. ### R14 — Account worker teardown lacks the join used by login
